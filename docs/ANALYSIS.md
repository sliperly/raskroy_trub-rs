# Анализ задачи и рассмотренные варианты

Ниже сохранены материалы из обсуждения задачи с чат-ботами на начальном
этапе. Они показывают, как был выбран подход. Итог: сначала реализован
вариант «скомпилированный .exe» на Python, затем программа переписана на
Rust (см. [README](../README.md)). Актуальные требования — в
[ТЗ](ТЗ_раскрой_трубы.md); значения констант (зажим, потери) там уточнены
и отличаются от первоначальных оценок ниже.

---

Анализ задачи
По сути это классическая задача раскроя материала (1D cutting stock / bin packing):
нужно разложить набор отрезков (заготовок) по «контейнерам» фиксированной длины
6000 мм с учётом того, что часть трубы (300 мм под зажимом) резать нельзя.
Ключевой момент про зажим: если зона зажима всегда находится с одного и того же
конца трубы (что типично для труборезов — зажим держит хвостовик, пока труба подаётся
и режется), то задача упрощается: полезная длина каждой трубы = 6000 − 300 = 5700 мм,
и дальше это обычная задача упаковки отрезков в «бины» по 5700 мм. Если это не так
(зажим может «мешать» в разных местах по ходу трубы), логика сложнее — надо будет
уточнить.
Алгоритм для самой раскладки — обычно берут First Fit Decreasing (FFD) или Best Fit
Decreasing (BFD): сортируем заготовки по убыванию длины, каждую кладём в первую
(или наиболее «подходящую») трубу, где она ещё помещается. Это простой алгоритм, даёт
близкий к оптимальному результат, и его несложно реализовать без сложных библиотек.

Первоначально рассмотренные варианты реализации без установки ПО

1. VBA-макрос прямо в Excel (рекомендую как основной вариант)
Ничего устанавливать не нужно — VBA встроен в Excel.
Можно повесить кнопку «Рассчитать раскрой» на лист.
Макрос читает данные с листа, считает раскладку по FFD/BFD, выводит результат
(номер трубы → список заготовок → остаток) на этот же или новый лист.
Минус: в некоторых организациях макросы заблокированы политикой безопасности
(тогда см. вариант 3).

2. Power Query (M-язык) — без макросов
Тоже часть Excel, макросы включать не нужно, работает через «Обновить данные».
Можно написать рекурсивную M-функцию с той же логикой FFD.
Минус: M менее нагляден для отладки/доработки, чем VBA, если возникнет желание
что-то поправить самостоятельно.

4. PowerShell-скрипт (отдельно от Excel)
Встроен в Windows, дополнительного ПО не требует.
Может читать/писать xlsx либо через COM-объект Excel.Application (Excel должен
быть установлен на машине — обычно так и есть), либо в csv, если экспортировать
данные из Excel вручную.
Запускается двойным щелчком (если настроена политика выполнения) или через
«Запуск с помощью PowerShell».
Удобно, если нужно потом гонять расчёт как отдельный batch-процесс или по
расписанию.

6. Скомпилированный .exe (например, из Python)
Конечному пользователю не нужен интерпретатор — просто двойной клик.
Но собирать exe нужно один раз (через PyInstaller и т.п.), и это отдельный шаг
подготовки. Можно сделать, если вариант 1–3 по каким-то причинам не подходит.
Дайте знать, какой вариант удобнее — и уточните момент с зажимом, тогда сразу сделаю
рабочий файл/скрипт.
